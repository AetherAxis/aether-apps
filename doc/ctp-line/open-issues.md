## 2. 持仓与查询记录

### #5 持仓其余字段仍是抓包常量
- **现状**：总仓（payload@54）与今仓（@150）2026-10-29 已真实化；`YdPosition` / `PositionCost` /
  `UseMargin` / `PositionProfit` / `CloseProfit` 仍是 2026-10-03 抓包里的值。
- **证据**：0..260 **全量单字节扫描**没有任何一个字节能影响这五个字段（捕获值 33790.00 / 4730.60 / -20.00 恒不变）
  ⇒ 要么是多字节定点/浮点编码，要么本帧压根没有这些槽。
- **下一步**（按顺序，别跳）：
  1. 拿一条**真前置**的持仓样本：昨仓非 0、成本/保证金非默认（SimNow 隔夜仓最容易造）；
  2. 用 `CtpFrontTemplates.QryPositionRecordHook`（`internal`，生产恒 null）做逐字节 patch-scan，
     **必须带阳性对照**（先改已知正确的 @54，确认补丁可见）；
  3. 定位后按 `Edit` 定宽写入；槽位定死前不要合并。
- **落点**：`ctp-net-front/src/Ctp.Net.Front/CtpFrontTemplates.cs`（`BuildQryPositionRsp`）。
- **细节**：`ctp-net-front/DESIGN.md` §3.10。

### #6 持仓量 >255 被截到 255
- **现状**：总仓/今仓都是 1 字节槽（0..255 实测逐值可用）。>255 时前置**截到 255 + 日志**。
- **为什么不直接加宽**：记录帧是定宽遍历的，多一个字节会让后续字段整体后移——那正是 2026-10-13 断连风暴的成因。
- **下一步**：要么从真前置抓一条 >255 的持仓样本、看它怎么编码（可能换成 `E7 <多字节>` 或走二进制族），
  要么接受截断并在桌面端做提示。**在有样本前，禁止「凭感觉撑宽」。**
- **落点**：同上；边界由 `FrontPositionFieldsTests.超过单字节槽的持仓_按255上报而不是写坏帧` 钉住。

### #7 查合约空结果不派发（客户端 30s 超时）
- **现状**：过滤到不存在的合约 ⇒ 前置直接不回帧；真前置会派发「空记录 + isLast」。
- **为什么不做**：op=01 转发空记录会让 SDK 交出无效指针 ⇒ C# `Marshal.PtrToStructure` 段错误（6.6GB core dump 那次）。
- **下一步**：需要一条 op=01 的**同会话请求 + 空应答配对帧**，把应答头做对再打开转发。
- **落点**：`CtpTrader.OnRspQryInstrument` 的空记录分支 + `CtpFrontSession` 查合约分支。
- **细节**：`ctp-net-front/DESIGN.md` §5「空记录回调不能盲转」、`ctp-net-front/FEATURE_MATRIX.md` §4。

### #8 查结算单非空正文未实现
- 只回 13B 空表（与真前置对「无结算单账户」的形状逐字节一致）。非空正文是分片大文本，槽位错即整帧被丢。
- **下一步**：找一个**真有结算单**的账户抓样本（SimNow 测试账户 4 个交易日全空）。
- **细节**：`ctp-net-front/DESIGN.md` §6 #6c。

### #9 查投资者（`ReqQryInvestor`）记录帧未逆向
- 请求/应答 op 已知（`E104E28008` / `E104E28009`），真前置实测 353B payload / 1 条记录；
  但记录把 60+ 字段按 `E1`(ASCII)/`E2`(GBK)/`E3`(int)/`E4`(浮点) 重复下发，槽位与定长约束没摸清。
- **下一步**：同 #5 的方法论（真样本 + 逐字节 patch + 阳性对照）。
- **细节**：`ctp-net-front/FEATURE_MATRIX.md` §3 第 3 项。

### #12 tick 没有毫秒槽、开高低/昨结昨收缺失
- 上报的 `updateTime` 是 8 字节 `HH:MM:SS`，`UpdateMillisec` 到不了客户端；
  开高低/昨结昨收在我们的帧里根本不存在（真前置是稀疏下发，字段 tag 未逆向）。
- **为什么不硬塞**：新造字段易错位（2026-10-13 同类事故）。当前消费方（Lean MM / noise-taker）只用 last/bid/ask/vol/oi。
- **下一步**：等有消费方需要（逐笔对齐 / 高频回放）再做，做法是从真前置稀疏帧反推各字段 tag。
- **细节**：`ctp-net-front/DESIGN.md` §5 与 §6 #7、`ctp-net-front/doc/md-tick-delivery.md` §7 第 3 条。

## 4. 交易语义与编码

- **#14 撤单按 `(账户, OrderRef)` 定位**：交易所账本 `_byOrderRef` 是覆盖写。改用 `OrderSysID` 需要交易所侧支持，
  牵涉面大；现阶段靠踢重 + 账本对账规避。
- **#15 错误码 >255 降级 148**：`WireError` 把超 1 字节的核心码映射成 148，真码只进 GBK 前缀。
  要做映射表 + 结构化槽，得先抓包确认槽位。
- **#16 模板文件仍含历史会话字节**：头注写着含 token/密文/账号，原抓包已清空。重生成可能改帧宽，
  多行/tick 未逆向前不要盲重生成。
