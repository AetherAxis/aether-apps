### #29 反向对账缺失：交易所侧多出来的活单永远不会被撤

- **已修（2026-10-31 15:2x，Lean 券商侧 `SweepOrphanOrders`，本地 probe1 实测）**：
  `ReconcileWithExchange` 现在每轮对账顺带做**反向清场**——交易所委托表里「活单（`1`/`3`）+
  本进程不跟踪 + 本进程订阅的合约」一律撤掉，连接后最多清 10 轮（交易所一次只回 200 行，#28）。
  三条边界写死在注释里：只清本策略摸的合约（别的合约可能是人在期货页下的）、只清 tracker 不认识的、
  轮数封顶（同一账户双进程是已知限制，不能无限互撤）。
- **它到底害了什么（2026-10-31 15:0x 定案，这才是真身）**：交易所按「**同向平仓挂单的剩余量**」
  预留可平量（`SimTradingCore.ReservedCloseVolume` → `AvailableToClose`）。历史会话留下的孤儿 BuyClose
  把这个账户的可平量**全部占光** ⇒ 新进程的每一张 BuyClose 都被 `[90006] 无可平持仓` 拒
  （单账户累计 **743 次**，前置日志可查）⇒ 做市商的**减仓侧一张都挂不上**，簿上只剩一侧。
  孤儿单还白占保证金与簿位。清场后本地实测：撤 11 条 → 再清一轮 9 条 → 90006 归零。
- **也解释了 #30 的一半**：活单数只增不减一路顶到 200 行，每轮对账都拿回「200 行全是活单」。
- **已有的一半**：`Aether.CtpConsole` 的直连路径本来就有启动清场（`SweepOpenOrdersAsync`，撤 176 张实测）；
  缺的是**引擎（Lean 券商）路径**和**单次运行期间**——现在补上了前者，后者由每轮对账兜（20s 一轮）。
- **落点**：`aether-trading/.../CtpBrokerage.Trading.cs`（`SweepOrphanOrders` / `ReconcileWithExchange`）、
  `CtpBrokerage.cs`（`Connect` 重置配额）。

### #30 「无缘无故断开」定案：客户端查询并发 + 前置写循环同步写盘（2026-10-31 16:2x 修并部署）

- **现象**：一个会话好好跑着，先「半死」十来秒——`下单 10s 未收到报单回报`、`持仓查询 5s 未返回`、
  `对账查报单 8s 未返回`、`ReqQryInvestorPosition 发送失败 rc=-2`、`ReqQryOrder 发送失败 rc=-1`——
  再撑几秒 CTP API 判死拆链路：客户端 `前置断开 reason=4097`，前置侧 `会话异常: Unable to read data
  from the transport connection: 远程主机强迫关闭了一个现有的连接`（客户端发 RST）。**前置没踢人**。
- **根因（前置）：唯一写 TCP 的线程在逐帧同步写盘。** 前置把**每一帧**出站字节 `Convert.ToHexString`
  后写日志，而写日志的地方就在 `WriterLoopAsync`——**唯一写 TCP 的线程**上；宿主
  `Console.WriteLine` 重定向到文件、逐行 flush。做市商每秒几十帧 ⇒ 每秒几十次「格式化 + 同步写盘」
  压在这条线程上。磁盘一抖，写循环跟着卡 ⇒ 报单回报、查询应答、心跳应答**全部排队发不出去** ⇒
  客户端那边就是「下了单 10 秒没回报、查持仓 5 秒没应答、对账查报单 8 秒没应答」，而 SDK 在
  这十秒里又往同一条管线塞请求 ⇒ `rc=-2`（未处理请求超过许可数）⇒ 再撑几秒 SDK 判死拆链路。
  **一句话：不是客户端发太快，是前置答不出来。**
  修法：`FrontFrameTrace.Enabled`（`AETHER_CTP_FRAME_TRACE=1` 才开，默认关），出站帧/入站帧/行情
  tick 推送行/报单·撤单 body 的十六进制全部进开关；**语义日志（会话/登录/报单/撤单/拒单/去重跳过）
  始终记录**。实测日志增速 24MB/小时 → **110KB/小时**（≈200×）。
- **止损（前置，与真前置对齐）**：读循环是**单线程串行** `await`——一笔查询在等交易所 RPC 时，
  这条会话后面所有帧（含心跳）都停在那次 await 后面。真前置是多线程的，一笔慢查询不会把心跳拖住。
  现在给单帧处理加**硬上限 4 秒**（`FrameProcessLimit`，短于客户端的 5s/8s 容忍）：超时即会话不可信，
  主动关闭让客户端重连，严格优于「半死十几秒后由 SDK 拆链路」。同时把 **>200ms 记为「慢帧」**并落日志
  （`慢帧 Nms len=… 前缀=…`）——以后谁慢一眼看得见。实测正常态**零慢帧、零超时**。
- **单笔失败不再炸整条会话（前置，与真前置对齐）**：旧行为是 `HandleBusinessAsync` 里任何 RPC 异常都穿到
  读循环 ⇒ 整条会话关掉，客户端看到「好好跑着突然断线」，真正原因只是某一次查询/报单的 RPC 失败。
  真前置对单笔请求失败是**回错误码、会话照常**。现在：单笔异常记日志并只丢该笔（`帧处理失败（丢该笔，
  不断会话）`），超时才断会话（那是「整条链路不可信」，性质不同）。
- **静默丢弃全部留痕**：六处 `if (reqId is not { } x) return null;` 原本一声不响——解析不出 reqId 就
  永远不回。现在每处都记 `查X：解析不出 reqId，未应答（前缀=… len=…）`，形态一变立刻能在日志里看到。
- **客户端侧（已回退为「只要不被 SDK 拒」）**：曾加过 1 秒限速当补丁，**2026-10-31 17:5x 撤掉**
  （`MinQueryInterval = 0`）——限速只是把「前置不回」掩盖成「我少发点」，还会让对账与持仓查询互相排队，
  反而制造超时。保留的只有「同一时刻只有一笔查询在飞」（`SemaphoreSlim(1,1)`），那是 CTP API
  自己的语义，不是我们加的节流。撤掉限速后 11 分钟实测：零断连、零 `rc=-2`、零查询失败。
- **已排除**（此前的假说，都验过不是）：前置主动踢人、客户端进程崩溃、行内容/行数本身、
  同账户双客户端（那是 #35，15:52 已消除，风暴从 139 次/15 分钟降到零）。
- **验收**：2026-10-31 17:48–18:00（**已撤掉客户端限速**，11 分钟）probe1 走前置：
  `前置断开 0`、`90006 0`、`持仓查询失败 0`、`发送失败 0`、`对账跳过 0`、`未收到报单回报 0`，
  两边恒挂（`买3/卖3`）；前置侧 `慢帧 0`、`帧处理超时 0`。修复前同环境 ~1 次断连/2.5 分钟。
- **落点**：`ctp-net-front/src/Ctp.Net.Front/FrontFrameTrace.cs`（新）+ `CtpFrontSession.cs`
  写循环/入站帧/慢帧与超时 / `CtpFrontMdSession.cs` tick 推送行；`ctp-net-core/.../CtpTrader.cs`
  （`RunQueryAsync`：只串行、不限速）。
- **仍待做**：半死窗口里攒下的**僵尸腿**（无回报、撤不掉）只靠重启清；见 #36 的收尾项。

### #34 Lean 本地风控替交易所拒单 ⇒ 做市商只剩一侧能报价

- **已修（2026-10-31 15:2x，本地 probe1 实测）**。现象是「策略以为自己在挂单，交易所一张都没收到」：
  `[MM] 挂卖 120.937500` 反复出现、`[Brokerage] 已报单` 一行都没有，日志里只有 Lean 自己的
  `Order Error: Insufficient buying power to complete orders (Value:[-118.41]), Initial Margin: -118.34, Free Margin: 0`。
- **两个独立机制叠在一起**（都必须修，只修一个会被另一个掩盖）：
  1. **持仓回填均价 = 0**（`CtpBrokerage.GetAccountHoldings` → `PriceFallback`）。启动时行情还没订阅，
     `GetLatestTick` 为空 ⇒ 均价 0 ⇒ Lean 把空头 12 手算成一笔巨额浮动盈亏，买入力当场算穿。
     **修**：回填时先把行情订阅提前、最多等 3s 拿第一笔真价（`FirstTickOrWait`），拿不到才退回 0 并留日志。
     （交易所侧的持仓成本/保证金字段在 CTP 线上还是抓包常量，#5 —— 只能拿行情兜。）
  2. **Lean 期货保证金模型与交易所算法不一致**：Lean 给每张挂单各锁一份保证金，交易所对**平仓单冻结 0**、
     且持仓保证金早已从可用资金里扣过 ⇒ 小额账户先被算成 `Free Margin: 0`，随后每张新单都被本地风控毙掉。
     **修**：`LeanAlgorithmBase.AddCtpData` 给每个 CTP 合约装 `NullBuyingPowerModel`——本地不再拦，
     订单照发，**拒单由真前置按保证金/可平量判定**（它判得准，且拒单会回报）。
- **为什么必须修**：这两条一起把做市商压成单边（实测：空 7 手 + 11 张买腿在挂 ⇒ 卖腿一张也报不出去），
  正是「市场没有对手盘」的另一半来源。修完本地 probe1 稳定双边：`在挂 买14/卖1`、400+ 行日志里
  90006 与买入力拦截均为 0。
- **落点**：`aether-trading/.../CtpBrokerage.Trading.cs`（`PriceFallback`/`FirstTickOrWait`）、
