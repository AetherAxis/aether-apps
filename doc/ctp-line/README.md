## 5. 红线（踩过的坑，别再踩）

1. **不要给记录帧「加宽」量槽/状态槽**——定宽遍历，多一字节就整体失步（2026-10-13 断连风暴）。
2. **不要在没有阳性对照的情况下做槽位探针**——「改了没反应」既可能槽不对，也可能探针没生效。
3. **不要把「去重跳过 N」当行情健康指标**——它衡量的是簿变更 vs 上报字段变化。
4. **不要在断连窗口里「重发」报单**——先查后补（对账），报单不幂等。
5. **结论被推翻时，必须 grep 全仓同一说法并一起改**——2026-10-30 的教训：「F0 序号只认 1~251」
   被推翻后，同一说法还活在 7 个文件里（含 `CLAUDE.md`），其中一条还被用来论证"为什么需要直连旁路"。
6. **不要把「进程活着」当「策略活着」**——引擎 `Error` 后进程可以躺平装死（#27：CPU=0、会话健康、
   计划任务 Running，24 分钟无人知）。无人值守路径一律非零退出码交给计划任务重启；
   对账/查询**失败只能跳过，绝不能反推**「交易所侧没了」（#25 的纪律，验收当晚就挡住一轮误杀）。
